# MVP Acceptance Matrix

This matrix maps the 13 acceptance criteria in [SPEC.md](../SPEC.md#18-mvp-acceptance-criteria) to durable automated evidence and the two presenter-led manual journeys in the [README](../README.md). Test names correspond directly to executable xUnit methods.

| # | Criterion | Evidence |
|---:|---|---|
| 1 | Submit one globally unique release ID through the web UI without a revision. | `ReleaseSubmissionTests.Complete_demo_fixture_persists_release_evidence_starts_workflow_and_redirects`; `Duplicate_release_id_returns_conflict_page_and_does_not_reopen_or_replace_release`; README passing journey. |
| 2 | MAF visibly fans out to Test, Security, and Change and aggregates one result from each. | `WorkflowTopologyTests.Real_graph_routes_once_per_branch_before_aggregation`; all `WorkflowScenarioTests` assert one three-result round; `ReleaseDetailPageTests.Full_detail_renders_current_results_evidence_round_reasons_wait_brief_and_timeline`. |
| 3 | All four branch outcomes exist without converting technical defects into domain results. | `BranchExecutionTests` covers missing evidence, deterministic blockers, exhausted known transient failures, and passing retries; `Unclassified_provider_failures_remain_technical_failures`; `WorkflowScenarioTests.Unexpected_provider_exception_is_a_visible_technical_failure`. |
| 4 | Multiple branch problems create one post-fan-in remediation request. | `WorkflowScenarioTests.Multi_block_remediation_executes_affected_checks_and_reuses_the_other`; `Missing_and_transient_results_fan_in_before_one_remediation_wait_and_resume`. |
| 5 | Evidence-only remediation executes only invalidated branches and reuses the rest without provider or policy calls. | `WorkflowScenarioTests.Multi_block_remediation_executes_affected_checks_and_reuses_the_other`; `SelectiveRerunTests.Reuse_makes_zero_provider_or_policy_calls_while_execution_calls_each_once`; README blocker/remediation journey. |
| 6 | Round history and timeline explain Executed versus Reused and link reused results to a source round. | `SelectiveRerunTests.Reuse_emits_a_new_result_linked_to_the_verified_source_without_execution_attempts`; `ReleaseDetailPageTests.Full_detail_renders_current_results_evidence_round_reasons_wait_brief_and_timeline`; README blocker/remediation journey. |
| 7 | A waiting workflow survives stop/restart and resumes once without duplicate business records. | `WorkflowScenarioTests.Remediation_wait_survives_restart_and_resumes_once`; `Approval_wait_survives_restart_and_approves_once`; `CheckpointContractTests.Restored_approval_wait_contains_only_the_checkpoint_request_reference`; `Restored_remediation_wait_contains_only_the_checkpoint_request_reference`; `Pending_wait_is_rehydrated_after_process_boundary_and_accepts_correlated_response`; README restart demonstration. |
| 8 | Deterministic C# decides Change readiness from approval and approved-window containment. | `ChangeReadinessTests.Missing_approval_or_approved_window_maps_to_missing_evidence`; `Unapproved_change_maps_to_blocked_without_a_reuse_deadline`; `Requested_window_must_be_fully_contained_with_inclusive_boundaries`; `Passing_change_uses_the_approved_window_end_as_its_reuse_deadline`. |
| 9 | A fully passing round creates an immutable snapshot and deterministic decision brief. | `DecisionIntegrityTests.Fully_passing_round_persists_one_snapshot_request_and_byte_stable_brief`; `DecisionContractTests.Decision_snapshot_captures_three_passing_sources_and_the_earliest_deadline`. |
| 10 | A correlated typed MAF approval or rejection terminates without returning to evaluation. | `WorkflowScenarioTests.All_pass_round_waits_for_approval_and_approves_once`; `Restored_approval_rejects_once_and_terminal_release_cannot_reopen`; `DecisionPageTests.Valid_decision_posts_only_audit_input_and_redirects_to_terminal_detail`; README passing journey. |
| 11 | Missing, mismatched, corrupt, or incompatible approval continuation fails before resumption and creates no human response. | `DecisionIntegrityTests.Invalid_continuation_is_rejected_before_creating_a_human_response`; `CheckpointContractTests.Invalid_checkpoint_approval_reference_fails_closed`; `Mismatched_request_is_rejected_without_consuming_the_pending_wait`; `RestartRecoveryTests.Approval_resume_rejects_a_checkpoint_and_database_request_identity_mismatch`; `DecisionPageTests.Missing_or_mismatched_continuation_has_no_human_response`. |
| 12 | Targeted deterministic, workflow, restart, and UI checks pass. | Root quality gate in `AGENTS.md`; focused commands in README; `WorkflowScenarioTests`, `RestartRecoveryTests`, `CheckpointContractTests`, and all tests under `Web/`. Manual UI evidence is the two README journeys. |
| 13 | The implementation remains one bounded application with no prohibited platform expansion. | `ReleaseReadinessCoordinator.slnx` contains one web project and one test project; `AGENTS.md` records the boundary; final diff review checks for extra deployables, queues, workers, brokers, event buses, SPA state, and browser automation. |

## Manual evidence checklist

- [x] Run the passing release and terminal human-decision journey.
- [x] Run the blocker/remediation journey and inspect Executed/Reused source linkage.
- [x] Stop and restart the host once at a remediation wait and once at an approval wait using the same application-data directory.
- [x] Confirm manual refresh, accessible labels/headings, safe continuation feedback, visible failures, and duplicate protection.

Automated evidence is deterministic and uses temporary SQLite databases and checkpoint directories. The owner completed the presenter-led checks; the project does not carry a browser-automation dependency.
